# Session: Prompt-Only Block Filtering via `includeInPrompt`

Read `CLAUDE.md` and `.planning/prompt-filter-spec.md` before starting.

This session adds `includeInPrompt` to `AuiPluginRegistry`, allowing host apps to
control which built-in block types are advertised to the AI in the generated system
prompt. Rendering is not affected — the `BlockRenderer` is not touched.

---

## Context

`AuiCatalogPrompt.generate()` currently advertises the full built-in block catalog.
Host apps want to trim this to just the types they use — for prompt size and AI focus.

**The key constraint:** filtering is prompt-only. `BlockRenderer` renders everything
regardless. Old conversations with filtered block types continue to render correctly.

Full design rationale: `.planning/prompt-filter-spec.md`.

### 1b. Add `allowedPromptTypes` field

```kotlin
private var allowedPromptTypes: Set<String>? = null
// null means "no filter" — full catalog is advertised (default behavior)
```

### 1c. Add `includeInPrompt` method

```kotlin
/**
 * Restricts which built-in block types are advertised in the AI system prompt
 * generated by [AuiCatalogPrompt.generate].
 *
 * Does NOT affect rendering — [BlockRenderer] renders all block types regardless
 * of this filter. This ensures old conversations with previously-advertised types
 * continue to render correctly after the filter is applied.
 *
 * Plugin component types are always advertised if registered; this filter applies
 * to built-in types only.
 *
 * Default (no call): full built-in catalog is advertised.
 *
 * @param types The [AuiBlock] subclasses to advertise. [AuiBlock.Unknown] is not
 *   a valid argument and will throw [IllegalArgumentException].
 */
fun includeInPrompt(vararg types: KClass<out AuiBlock>): AuiPluginRegistry {
    allowedPromptTypes = types.map { klass ->
        blockTypeMap[klass] ?: throw IllegalArgumentException(
            "${klass.simpleName} is not a known built-in AuiBlock subclass. " +
            "Do not pass AuiBlock.Unknown, and make sure blockTypeMap is up to date."
        )
    }.toSet()
    return this
}
```

### 1d. Add `isAllowedInPrompt` internal helper

```kotlin
/**
 * Returns true if [wireType] should be included in the generated AI prompt.
 * Always returns true when no [includeInPrompt] filter has been set.
 * Internal — used by [AuiCatalogPrompt] only.
 */
internal fun isAllowedInPrompt(wireType: String): Boolean {
    return allowedPromptTypes?.contains(wireType) ?: true
}
```

## Part 2 — `AuiCatalogPrompt` changes (`aui-core`)

File: `aui-core/src/main/kotlin/com/bennyjon/aui/core/AuiCatalogPrompt.kt`

`generate()` already iterates a list of built-in component type strings to build the
"Available Components / Built-in" section. Locate that iteration and wrap it with a
filter call:

```kotlin
val advertisedBuiltIns = ALL_COMPONENT_TYPES.filter { wireType ->
    pluginRegistry.isAllowedInPrompt(wireType)
}
```

Use `advertisedBuiltIns` in place of `ALL_COMPONENT_TYPES` when building the prompt
output. No other changes to `generate()`.

Plugin schemas from `pluginRegistry.allComponentPlugins()` are **not filtered** —
they are always included when registered.

```markdown
### Filtering the prompt catalog

By default, `AuiCatalogPrompt.generate()` advertises all built-in block types.
For focused apps, you can restrict this to only the types you use:

```kotlin
val registry = AuiPluginRegistry()
    .register(AddToCartPlugin)
    .includeInPrompt(
        AuiBlock.Text::class,
        AuiBlock.Heading::class,
        AuiBlock.ButtonPrimary::class,
        AuiBlock.QuickReplies::class,
        AuiBlock.InputRatingStars::class,
    )
```

This reduces prompt size and helps the AI pick components more purposefully.
Filtering is prompt-only — the renderer still handles all block types, including
those in older conversations that predate the filter.
```

## Do Not

- Do not modify `BlockRenderer` — rendering is not affected by this feature
- Do not add `excludeFromPrompt` — allowlist only, per design decision
- Do not filter plugin component types — `includeInPrompt` is for built-ins only
- Do not change `AuiPluginRegistry.Empty` behavior — it has no filter, full catalog
- Do not modify `AuiBlockSerializer` or `AuiParser`
- Do not modify `AuiBlock` sealed class
